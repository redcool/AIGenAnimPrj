## 3. 日常怎么跑

### 3.1 生成动作（最常用）

Windows 侧直接调用（推荐，因为要去 WSL 里跑）：

```powershell
wsl -e bash /mnt/h/aiworks/motionPrj/AIGenAnimPrj/scripts/unimate-sample.sh --asset assets/examples/unitree_go2 --prompt "An object trots forward." --num_repetitions 2
```

多个 prompt / 多个资产：

```powershell
wsl -e bash /mnt/h/aiworks/motionPrj/AIGenAnimPrj/scripts/unimate-sample.sh `
  --asset assets/examples/eagle assets/examples/shark `
  --prompt "An object flaps its wings." `
  --num_repetitions 3 --output_dir outputs/samples/mine
```

常用参数：

| 参数 | 作用 |
|---|---|
| `--asset` | 资产目录（`rig_preprocess` 产物）、`dataset:object_type`、或 `cond.npy` |
| `--prompt` | 句式照训练集：`An object ...`，只描述一个动作 |
| `--num_repetitions` | 同一 prompt 采样几次 |
| `--cfg_scale` | 默认 3；不听话调到 5~7，想更平缓调低 |
| `--seed` | 固定种子复现 |
| `--only_save_motion` | 跳过 mp4/PNG 渲染，只写 .npy（快） |
| `--output_dir` | 默认 `<exp_dir>/samples`；同一个目录会累加，manifest.json 记录全部 |

### 3.2 把动作套到网格上（导出 GLB/FBX）


## 4. 这台机器上踩过的坑（都已修好，重装时可复用）

| 坑 | 现象 | 处理 |
|---|---|---|
| WSL 完全没网 | apt/curl 全超时（只有 IPv6 解析、无路由） | `%USERPROFILE%\.wslconfig` 加 `networkingMode=mirrored`（原文件备份为 `.wslconfig.bak`） |

| HF 下载卡死 | `Fetching 3 files` 停在 2/3，缓存 0 字节 | 设 `HF_HUB_DISABLE_XET=1`（xet 后端在本网络下挂住），走普通 HTTP |
| 仓库脚本是 CRLF | `$'\r': command not found` | 30 个 `.sh` 已转 LF；repo 内 `core.autocrlf=false` |
| 没有 blender 可执行文件 | `blender: command not found` | 写了个 shim `.../envs/unimate/bin/blender`，把 `blender -b -P s.py -- args` 转成 bpy 跑 |

## 7. Mixamo 人体路线（已跑通）

所以先用精简脚本削成 22，再做采样。

```powershell
#   -> Arts/X_Bot_simplified.glb + X_Bot_simplified.report.json

# 2. 进管线：打关节标签、烘 canonical 骨架
wsl -e bash -lc "cd /mnt/h/aiworks/motionPrj/UniMate && CONDA_ENV=unimate /home/gamebox/miniforge3/envs/unimate/bin/python -m data_process.rig_preprocess run --input '/mnt/h/aiworks/motionPrj/Arts/X_Bot_simplified.glb' --output_dir outputs/rig/X_Bot --name X_Bot --no_review"
#   -> outputs/rig/X_Bot/{cond.npy, X_Bot.glb, preview.png, summary.json}
#   summary.json 里 model_joint_limit.fits 必须是 true，preview.png 里人要站直、面朝 +Z

# 3. 采样 + 导出
```

## 9. 一条龙脚本（推荐入口）

`unimate-pipeline.sh` 把五个步骤串起来，**每步都先判断能不能跳过**。

```powershell
# 默认：待机 / 走步 / 跑步 各采 3 次
wsl -e bash /mnt/h/aiworks/motionPrj/AIGenAnimPrj/scripts/unimate-pipeline.sh --input "Arts/X Bot.fbx"

# 自定义 prompt
wsl -e bash /mnt/h/aiworks/motionPrj/AIGenAnimPrj/scripts/unimate-pipeline.sh --input "Arts/robot.glb" `
  --prompt "An object walks forward." --prompt "An object jumps in place." --reps 2
```

| 步骤 | 做什么 | 跳过条件 |
|---|---|---|
| 1 体检 | `inspect_rig.py`：关节数、权重覆盖、动画 | 不跳（只读，几秒） |
| 2 精简 | 只在**超标**时跑 | 关节数 ≤ 目标关节数 |
| 3 rig_preprocess | 打标签、烘 canonical | `outputs/rig/<name>/cond.npy` 已存在（`--force` 强制重跑） |
| 4 采样 | 每个 prompt × `--reps` 次 | 不跳 |
| 5 导出 | GLB + FBX | 不跳 |

**目标关节数怎么定**（这是关键）：

| 权重目录 | 目标 | 原因 |
|---|---|---|
| 名字带 `mixamo`（人体专用） | **22** | 它只吃 22 关节 Mixamo 骨架 |
| 其它（通用 `uniml3d`） | `--max-joints`，默认 **71** | 模型上限 |

所以一个 65 关节的 Mixamo 角色，用人体专用权重时**照样会被精简到 22**，不是"没超 71 就不管"。
想手动控制就加 `--target-joints N`。

其它参数：`--drop "Finger|Twist"`（非 Mixamo 骨架的删骨规则）、`--keep`、`--exp-dir`、`--out`、
`--stop-after inspect|simplify|rig|sample`（每步停下来看）、`--dry-run`（只打印计划）。

## 11. 循环化（待机 / 走 / 跑）

### 为什么生成的动作不能直接循环

三个原因叠在一起：

1. **固定 60 帧窗**：模型每次生成 2 秒，起手是随机噪声，首尾没有约束。
2. **训练没有周期约束**：训练目标是"像这段动作"，不是"首尾相接"。
3. **根节点在往前走**：模型学的是"向前走"，24 帧里 Hips 前进约 1.8 个单位。
   直接循环 = 最后一帧在 1.8 米外，下一帧弹回原点。

### 三步解决

```powershell
wsl -e bash /mnt/h/aiworks/motionPrj/AIGenAnimPrj/scripts/unimate-loop.sh `
  --samples UniMate/outputs/samples/X_Bot_locomotion `
  --name X_Bot --rig UniMate/outputs/rig/X_Bot/X_Bot.glb
```

| 步骤 | 工具 | 做什么 |
|---|---|---|
| 1 找周期 + 接缝淡化 | `tools/make_loop.py` | 在 20~58 帧里找姿态最接近第 0 帧的一帧，切出来；把开头 K 帧朝 `x[L..L+K)` 混合，让"末帧→首帧"等于普通的一步 |
| 2 导出 | `run_animate_motion.sh` | 帧数变成周期长度 |
| 3 拉平根位移 | `tools/flatten_root.py` | 按帧减掉一条线性斜坡，首尾相消，动作变原地 |
| 4 打包 Unity | `tools/bundle_unity.py` | 角色 FBX + `anim/idle_0.fbx`… + 带循环质量表的 README |

### 实测效果（X Bot，接缝 = 末帧到首帧的跳变 / 普通一步）

| 动作 | 原始 | 加循环 | 再加原地 |
|---|---|---|---|
| run_0（24 帧） | 17.1 倍 | 6.2 倍 | **0.86 倍** |
| run_1（24 帧） | 17.5 倍 | 6.7 倍 | **1.09 倍** |
| walk_2（35 帧） | 23.9 倍 | 13.4 倍 | **1.32 倍** |
| idle_0/1/2 | 24.5 / 13.9 / 19.9 倍 | 1.2 / 2.5 / 8.8 倍 | 0.00（收拢到同一帧） |

结论：**先找周期、再拉平根位移**，两个动作一起做才有用。只做周期不减根位移，接缝仍有 6 倍（因为人在往前走）。

### 不是每条都能救

9 条动作里只有 3 条（run_0、run_1、walk_2）检测到周期。
其余 6 条首尾差太大，只能"整段收拢"（结尾一帧停顿），或者重新采样。
`loop_report.json` 里每条都有 `loop_verdict`，按它挑就用最好的。

**建议做法**：一次采 5~6 次（`--reps 6`），跑完 `unimate-loop.sh` 看排名，挑每类里倍数最小的那条进 Unity。

### 判定口径

| 指标 | 含义 |
|---|---|
| 接缝倍数 | 首尾差 / 该动作平均每帧步长。越接近 1 越好 |
| 接缝绝对值 | 首尾差的绝对大小。待机这种微动倍数会很大（20+）但绝对值只有 0.03，看不出来 |

### 想更好还能做

上面的做法是**后处理**。更彻底的是让模型自己闭环：把尾段几帧钳成首段，用 in-betweening 的替换式采样重新去噪中间——
仓库里 `unimate/inference/motion_inbetweening.py` 提供了 `build_keep_mask`，技术上可行，但要多写一个采样入口。
先看后处理的效果，不够再上这个。

## 12. 模型闭环（试过了，结果如下）

### 做法

思路是 in-betweening 的替换式采样（RePaint，flow matching 下解析插值即可，一次正向积分就够）：

1. 把生成的 .npy 归一化回模型空间；
2. 造一个 `x1_known`：末帧 = 首帧姿势，`keep_mask` 只标那几帧；
3. 跑 50 步 `inbetween_sample_ode`，被钉住的帧每步都被替换回插值，中间由模型重新去噪；
4. 反归一化存回，丢掉重复的最后一帧（60 -> 59）。

工具：`tools/loop_close.py`，接在 `unimate-loop.sh --close` 上。

### 关键细节：钉 1 帧不够，要钉 2 帧

只钉末帧（`--pin-tail 1`）能让首尾姿势相同，但模型会"赶"到终点，接缝处速度突变。
改成钉 2 帧，并且用**速度外推**填末帧：

    x[T-1] = x[0]
    x[T-2] = x[0] - (x[1] - x[0])

等于同时约束了位置和速度，收尾不会急停。效果差别很大。

### 实测（骨架层面的接缝倍数，1.0 = 和普通一步一样）

| 动作 | 原始 | 后处理 | 闭环钉 1 帧 | 闭环钉 2 帧 |
|---|---|---|---|---|
| run_0 | 17.10 | **0.86**（24 帧） | 1.69 | 2.39 |
| run_1 | 17.50 | **1.09**（24 帧） | 2.05 | 1.97 |

### 结论：两条路线各有适用场景

| 情况 | 用哪个 | 理由 |
|---|---|---|
| 能检测到周期（倍数 ≤2） | **后处理**（剪切 + 淡化） | 0.86~1.32，保住了动作相位和速度 |
| 检测不到周期 | **模型闭环（钉 2 帧）** | 首尾真正接上，没有一帧停顿 |
| 待机这类无周期微动 | **模型闭环（钉 2 帧）** | 从 11~33 倍降到 1.4~2.2 倍 |
| 怎么都不行 | 多采几次 | 一次几十秒，比硬调便宜 |

### 还没解决的

闭环只保证"首尾姿势 + 速度接上"，**不保证周期正确**。走路如果周期不对，接缝是顺的，但步态节奏还是可能别扭。
真要彻底解决，得在采样阶段就约束周期（改模型或改训练），属于另一个量级的工作。

## 13. 关键修正：循环起点不一定在第 0 帧

用户观察：**生成的动作里本来就含完整的一段循环，只是没对齐到第 0 帧**。
所以正确做法不是"从头切到某帧"，而是**起点和终点一起搜**。

### 改了什么

`tools/make_loop.py` 里的 `find_cycle` 现在同时遍历：

    for L in [20, 58]:
        for s in [0, T-L-1]:
            cost = 姿态差(x[s], x[s+L]) + 0.5 * 姿态差(x[s+1], x[s+L+1])

- 第一项保证首尾姿势一致；
- 第二项保证**下一帧也一致**，也就是速度接得上（这一项很关键，缺了会"到点急停"）；
- 代价接近时优先更短的周期、更靠前的起点。

旧的"只从第 0 帧找"保留为 `--anchor`，用来对比。

### 效果（骨架层面的接缝倍数，1.0 = 和普通一步一样）

| 动作 | 原始 | 只从 0 帧找 | **全程搜起点** | 模型闭环 |
|---|---|---|---|---|
| run_0 | 17.10 | 0.86 | **0.93**（24 帧） | 2.39 |
| run_1 | 17.50 | 1.09 | **1.02**（23 帧） | 1.97 |
| run_2 | 16.42 | 3.1（收拢） | **0.62**（26 帧） | 2.34 |
| walk_0 | 17.25 | 8.1（收拢） | **1.10**（38 帧） | 4.89 |
| walk_1 | 22.73 | 6.1（收拢） | **1.08**（35 帧） | 2.16 |
| walk_2 | 23.85 | 1.32（35 帧） | **0.83**（36 帧） | 5.05 |
| idle_0/1/2 | 24/14/20 | 收拢 | 收拢（本来就没周期） | **1.36~2.21** |

**6 条走/跑全部落到 0.62~1.10**，比"只从 0 帧找"（只有 3 条能到 1.3 以内）强得多，
也全面优于模型闭环。之前那 3 条被判"无周期、建议重新采样"的，其实周期都在轨道中间。

### 最终推荐配方

| 动作类型 | 路线 | 结果 |
|---|---|---|
